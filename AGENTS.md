# K2040 Android Releases Repository Instructions

## Purpose

This public repository hosts the K2040 Android Projects website/catalogue and preserves historical release records that already belong here. New K2040 app releases should be published from each app's public source repository unless a documented exception is explicitly approved. This repository is not a private development or storage area.

## Keep the repository public-safe

- Everything committed or uploaded here must be safe to make public.
- Do not store passwords, tokens, signing or recovery material, private test data, personal data, device IDs, private links or IDs, machine-specific paths, private backups, or maintainer-only records here.
- Do not use this repository as temporary private storage.

## Release files

- Preserve existing published release files, checksums, notes, and historical links that already belong to this repository.
- Do not add new APKs here as the normal release workflow when the app has its own public source repository.
- New app releases, release files, checksums, and release notes belong in the relevant public app repository unless a documented exception is approved.
- If a historical release here must be maintained, publish only files approved for the correct app and version.
- Before publishing or replacing any historical release material, confirm that the app, version, file, checksum, and signing information match the intended release.
- Keep release notes and checksums matched to the exact published file.
- Do not publish private test or debug builds as normal releases.
- Keep private diagnostics, signing files, keys, and real user backups out of the repository.

## Public writing

- Write README files, website text, security/privacy pages, install guides, issue forms, and other public text in natural, simple language.
- Avoid developer jargon and implementation details unless they are needed for installation, verification, security, bug reporting, or troubleshooting.
- Explain necessary technical details in plain language whenever possible.
- Keep licence and attribution notices that must stay with published files.
- Put source-build, contributor, current release, and app-specific development instructions in the relevant source repository unless they are genuinely needed here.

## Safety checks

- Release files must have a clear, trusted origin.
- Stop if the app, version, signer, checksum, source, or release notes do not match what is expected.
- Do not accept unexplained files or assets.
- Website download links must point to the actual authoritative source for that published version.

## Release publication

Creating a release, uploading or replacing a release file, changing official release notes or checksums, or otherwise changing published release state is an official release action and remains maintainer-controlled.
